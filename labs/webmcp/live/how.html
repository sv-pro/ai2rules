How it works

With WebMCP a web page declares its own functions as tools, and an agent in the browser calls them instead of clicking. Whoever brokers those calls decides what reaches the page. That is where ai2rules sits.

1 · Pages declare tools

Each page calls document.modelContext.registerTool with a name, a description and an argument schema. The agent sees those tools and calls them by name. Browsers do not ship WebMCP yet, so the lab's shim provides the same interface.

2 · The broker decides

Every call passes the broker before the page runs it. ai2rules answers from a world compiled for this assistant: which tools exist, which registration each name must be, and what data may go where. No model takes part in that decision.

3 · Labels follow values

What is read from a private site (the CRM) is labelled private. Every argument of a tool on another site accepts only public values. A value the broker cannot vouch for takes the session's label, which turns private after the CRM read. So the leak is refused, and the gift order still goes through.
